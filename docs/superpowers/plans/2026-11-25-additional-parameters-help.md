# 附加参数格式示例与填写说明

**Goal:** 修复中文版附加参数窗口的不可用 YAML 示例，使已有值的字段仍有可访问标签和格式说明；小屏下使用现有弹窗滚动机制。

**Architecture:** `customEndpointAdditionalParameters.html` 继续拥有三个实际字段；`openai.js` 继续通过原生 input 回调修改所选 source bucket 并调用原保存入口。只修改模板、中文文案与现有弹窗选项，不增加解析器、校验路径、状态、副本、保存机制或外部契约。

**Tech Stack:** 原生 HTML、现有 i18n／Popup／YAML vendor 和生产 Browser Runtime。

## 证据与边界

在生产入口 `#customize_additional_parameters` 打开填有数据的实际弹窗，中文版 Include Body／Include Headers 占位示例分别为 `top_k：20` 和 `CustomHeader：自定义值` 等全角冒号写法。现有 YAML vendor 将两组都解析为 string，后端共同 map parser 只接受对象或对象列表。Exclude Body 的数组示例正常，保留其语义。

同一弹窗的三个字段均无可访问名称／description；说明只在 placeholder，字段已有值时无法看到。输入回调和实际请求参数验证正常，未确认保存或解析机制存在新缺陷。最初探针包含了 Popup 自身的隐藏输入，收窄到这三个实际字段后保存真实 RED；没有把探针定位失误当成产品问题。

用户已授权持续改进填写细节，不请求例行方案确认。延续 `feature/mobile-chat-shell`，暂存区为空；五个本项 baseline 与原有修改隔离，不提交、推送或修改无关内容。对低影响的静态标签／文案修复不新增永久字面量测试；复用现有行为覆盖，以一次性生产弹窗探针检查实际可访问名称、持续说明、示例解析与原请求参数。
