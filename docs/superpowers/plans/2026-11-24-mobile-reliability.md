## 404 后续排查：真机事实

- Redmi Note 11T Pro，Android WebView 157.0.8103.50，正在使用个人版 `com.tauritavern.personal`。
- API 地址、模型和 active 密钥均存在于手机数据目录。当前协议是 `openai_responses`，实际失败地址为 `https://odyfree.spinsnow.fun/v1/responses`。

- 历史原生 Gemini 请求曾因额外参数 `chat_template_kwargs` 被拒绝；另一条成功请求耗时约 77.6 秒。这是 API 响应耗时，不能算作应用启动耗时。
- 现有手机页面没有呈现原生 Custom endpoint preview；选择 API 来源或模型时只触发事件并关闭编辑器，没有等待原有显式保存入口确认。

## 404 的修复边界与验证

修正实际连接时使用原生来源选择和共同设置保存入口，保持用户的地址、密钥及完整模型 ID。重新连接后已把来源选为 `custom` / `openai_compat`，保存返回 `true`，请求预览是 `/v1/chat/completions`。应用自身的简短请求及冷启动后的 `generateRaw` 请求均已成功，具体耗时见下。

错误呈现沿现有 `UpstreamFailure` → command → AI route 的共同链路扩展 HTTP 404：保留服务端原始说明，显示经过凭据清洗的实际请求地址，以及检查 Base URL、协议和模型的操作说明。404 为不可自动重试的接口错误；不根据服务域名或模型名修改协议，不自动尝试其他接口。

模型列表成功只显示“已获取模型；请测试消息验证聊天接口”，不继续显示笼统的“有效”。验证用已有 HTTP repository 行为测试与 AI route 覆盖检查错误链路，已有 browser API 控件测试检查来源切换和模型列表状态。

### 保存与世界书格式

独立审阅复现了旧密钥读取覆盖已确认状态，以及预设/世界书选择确认过早。密钥读取 owner 只发布最新读取结果，较早调用共同等待新读取。预设名称和字段由原生 owner 在 BEFORE 完成后一起应用，随后发送 AFTER/PRESET_CHANGED；共同保存只捕获已应用状态，手机选择确认等待完整原生操作。用 BEFORE、AFTER 和 PRESET_CHANGED 内的实际 `PresetManager.writePresetExtensionField()` 验证保存不会与通知循环等待。全局世界书选择在 `getWorldInfoSettings()` 序列化时投影，读取设置不取消待保存编辑；所有保存入口共用原有保存与临时长度恢复机制。

手机已有 CharacterBook 数组格式的世界书，但原生世界书文件读取未经规范化，角色回写要求对象 entries 而报错。将现有纯 JSON CharacterBook ↔ World Info 规则移到 `tt-domain` 供用例与存储边界共用；文件 parsing/发布仍在 userdata adapter。文件读、导入和 byte commit 经同一 document 规范化入口，数组转为原生对象 entries；旧文件读取不改写，完整原文结构保留为 `originalData`，普通对象格式保持原始 bytes。角色回写按条目 ID 保留原始未知字段。用真实文件仓储核对读取、导入、commit 和原文件保护，不追加按 MVU 名称的路径。

数组识别正向校验 CharacterBook 的关键词、内容和启用字段，不再把原生字段数组静默转错；缺省编号和排序仍兼容已有导出。覆盖导入以现有精确名称经过同一文档校验和原子发布，成功前不业务删除或解绑，失败保留旧 bytes。针对性浏览器和仓储测试分别观察到旧路径的丢失/静默错转，再确认修复后数据保留。

标准预设 body 在 BEFORE 保存时曾被二次转换，导致温度字段丢失；保存 helper 统一接收序列化 body，UI 写入者显式转换，旧 PromptManager 迁移返回保存 Promise。使用标准格式 fixture 复现字段丢失，并以确定的阻塞 IO 验证迁移完成前不会提前应用新预设。

真机当前开启预设关联连接，而 catalogue 保存的是另一种 API 来源。生成参数手机页补出这个原生选项和说明，让用户可以只切换生成参数；既有连接选择继续由原生 owner 保存。完整检查的 104 项浏览器测试通过，契约测试 451 项通过，macOS Icon Composer 项因本机没有 Xcode `actool` 失败。剩余 UI、Rust 和 Clippy 检查单独继续执行，不能将完整 harness 描述为全绿。
