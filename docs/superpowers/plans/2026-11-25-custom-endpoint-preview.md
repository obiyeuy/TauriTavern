# 自定义 API 地址预览的填写校验

延续 `feature/mobile-chat-shell`，保护已有修改及空暂存区；用户已授权日常填写细节修复，不请求例行审批、不提交或推送。当前深度优化 APK 构建完成并核对输入前，不修改其生产输入。

## 证据和设计

`getCustomEndpointPreview()` 直接拼接输入；实际调用已确认带账号/密码、查询参数、片段及 FTP 地址都作为请求 URL 返回。唯一生产调用者 `updateCustomEndpointPreview()` 原样显示它。Rust 的 `parse_user_http_endpoint()`/`parse_endpoint_base()` 已拒绝这些基础地址，生成规则不需要改变。

沿填写失败链路又确认 Custom/Azure 的无效 URL 诊断把原始输入写入 debug 日志。模拟密钥元数据、实际连接按钮及标准失败状态下，误填的测试密钥出现在日志参数，已保存 RED。删除这两处原始值参数，保留来源诊断、可见错误和原网络验证。

现有 helper 继续拥有协议后缀与预览，非空输入只在符合已有 HTTP 基础地址规则时产生 URL；不支持的输入返回明确的无效状态。显示入口把这个状态呈现为填写说明，不能清洗掉非法部分再伪装成可用请求。正常地址的版本路径、Gemini 模型与 streaming 后缀、空字段的占位提示保持。实际网络验证和生成仍由原入口及后端拥有。

不增加 provider、端点自动重试/切换、保存格式或其他外部契约；不修改通用 URL validator。预览不是连接成功证明。
