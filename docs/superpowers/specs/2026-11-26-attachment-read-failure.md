# 附件读取失败终止内容消费

实际 Data Bank 移动操作中，原件 GET 返回 500 后，`getFileAttachment()` 提示错误但返回 `undefined`。移动函数把它构造成文字 `"undefined"`，成功上传后删除原件。编辑、查看、下载、聊天正文组装与向量入库也消费同一个失败缺省值。

读取成功仍返回文件的原字符串，包括空字符串；HTTP、传输与响应体读取失败拒绝 Promise，不产生文件内容，也不在读取函数弹通知。沿用第一方 `requireOkResponse()` 和原资源路由，不新增公共宿主接口、错误类型或数据状态。

Data Bank 的查看、编辑、下载、移动与消息文件打开控件接管拒绝并显示一次原有文件读取提示。失败不得打开空编辑器／查看器、创建下载、上传替代文件、删除原件或修改引用和禁用状态。`/db-get` 继续交给原命令执行器处理拒绝与通知。

核心聊天正文组装传播失败，不发送缺少附件内容的请求；读取结束前不修改该消息的 `fileLength`。发送、继续、再生成和模拟共用组装边界呈现一次附件读取错误，quiet 请求保留原调用者的提示责任。向量功能沿原 `rearrangeChat()` 可恢复边界提示跳过检索。单条消息全部必要读取与检索成功后才替换正文，失败保留完整原文。显式全部文件入库按钮接管读取失败；已有索引继续跳过读取，不因这次严格错误传播变成失败。

验证扩展原 Browser Runtime 的真实控件、Popup、slash parser、聊天请求与向量入口；合成 I/O 不访问真实用户文件或外部模型。覆盖 HTTP、传输／正文读取失败，以及同一流程后续正常读取。其他附件保存确认、删除结果和转换失败问题继续单列，不声称本项已修复。
