# API 测试等待反馈

目标：内置短测试从原生按钮启动，耗时请求期间持续显示等待并阻止重复提交；成功、失败或取消后，当前手机设置行立即恢复。用户报告加载慢，实际请求 69 用时 189.238 秒；确定性探针显示原按钮和手机行都没有 busy、disabled 或等待文案。

方案：把既有 `#test_api_button` 改为同 ID 的原生 `button[type=button]`，由这个控件的 disabled 状态取代内部 `apiConnectionTestPending`。原处理器在调用生成前设置 disabled、aria-busy 与“Testing API…”文案，finally 恢复，并通过标准 change 通知原状态变化。手机设置页复用原控件状态和 change，不维护第二份请求状态，也不靠定时猜测完成。

取舍：只增加内部布尔值的可视镜像会保留两份事实；为手机再启动请求或新建网络状态管理器会分裂生成链。选择由原控件拥有操作状态，已有设置行消费它。短期 settle 仍服务于原异步控件，不承担请求完成判定。

边界：

- 保留原按钮 ID、原 click handler、短测试提示词、64 token 上限、当前 API 格式、扩展 prompt-ready 事件、生成停止语义与结果提示。
- 不改变聊天生成互斥、状态查询寿命、地址、模型、密钥或设置持久化。
- disabled/aria-busy 是同一控件的交互与语义表现，guard 读取原 disabled，不保留原 pending 布尔值。
- 手机行显示原控件等待文案，普通状态继续使用 schema 的简短标签；成功或失败都从原控件 change 立即刷新。
- 设置页 change 订阅在 dispose 时删除，重建和重新打开读取当前 source；不增加 MutationObserver、轮询或延时阈值。
- 原按钮或手机行的重复点击不增加网络请求；失败继续由原测试按钮通知一次。
- 只改既有界面，不引入第三方 UI 库、动画或额外配置。
- 手机已拔出，本轮在电脑复现和验证；不宣称真实接口成功或新包已安装。

验证：实际 browser runtime 中挂起扩展准备与原生成请求，检查两个控件状态、请求数、完成反馈、重新打开页面及成功／失败恢复。测试在已存在的 API controls 行为覆盖中增加；原测试参数和一次错误覆盖继续运行。完整检查、自审与独立审阅后归档。
