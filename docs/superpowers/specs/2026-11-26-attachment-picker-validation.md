# 文件选择验证、操作归属与媒体读取

原实际选择控件、重置按钮和消息附件准备入口已复现：取消后重新选好文件，旧验证失败清空新选择，旧验证成功覆盖当前名字／数量；File.text 拒绝只有返回的 Promise 错误，UI 没有通知并保留旧标签；验证等待期间直接准备消息，二进制内容仍被上传。16 MiB 媒体的五次选择均先读取全文，正确 form reset 条件下中位 51.272 ms。证据在 `output/verification/attachment-picker-20261126/probe-results.json`，没有真实上传或模型请求。

选择与准备共用一条验证规则。私有 `getFileValidationError(file): Promise<Error|null>` 从原 MIME／size／converter 规则判断，已知不支持返回原说明的 Error，允许返回 null，实际读取失败拒绝原错误。媒体与超限判断只依赖元数据，先完成这两项，媒体不再为了随后忽略的二进制判断读取正文。非媒体的原二进制规则、限制、编码和转换器匹配不变。

`populateFileAttachment()` 在每个工作文件的首次读／上传前验证并核对聊天目标，失败继续原准备拒绝和部分已上传路径的 cause。原 API、发送和嵌入都不能依赖选择器已经验证的假定；不更改 raw base64 文件存储接口或成功字段。文本多一次准备验证是正确性取舍，不缓存 File.text、validity 或 converter 状态；媒体验证不读取正文，实际上传仍使用原字节读取。

主选择器在首次异步前捕获 input、File 对象和活动聊天位置。文件名／数量／大小仅来自选择元数据，先显示当前真实选择，验证后只修改仍属于本操作的输入。活动聊天的 reset 在等待前注册，回调仅清理该位置改变且仍对应本次选择的输入。welcome 的原未绑定草稿仍可随首次选择的聊天继续。旧结果或旧错误不覆盖、清空或通知新选择，不新增 operation ID、镜像、缓存或旁路。

验证只产生结果，不直接通知。主选择器、嵌入和 Data Bank uploader 各按实际 ownership 呈现原不支持说明；主输入／嵌入仍保留原 error 加 warning 的已知拒绝表现，Data Bank 无路径及单条说明保持。读取错误由当前主选择器一次呈现，保留真实选择和可清理的文件行；旧操作失去选择／位置后结束，不显示旧错误。嵌入在每次验证完成后先核对目标和选择，再呈现拒绝；Data Bank 在同一 source 确认后处理拒绝，错误和原有效重试路径保持。

发现 happy-dom 的 form reset 只改 input value 内部状态而保留赋值的 FileList。证据中的第一次“取消”不代表浏览器真实清空，不能计作生产数据丢失。公共 Browser Runtime 补齐未被取消的文件 reset 默认动作后，再用相同实际按钮复现上述清空和标签错误。该修正只在测试运行时，不在生产中补偿；保留 reset 取消语义。相关 baseline 增加 `tests/browser/runtime.mjs`。

复用最高层附件 fixture：两类旧结果、新角色／welcome、当前读取失败／重试、待验证输入的实际准备拒绝、媒体读取边界、Data Bank 已知拒绝／无路径。相关原准备、嵌入、保存、删除和媒体请求继续覆盖。相同条件重跑媒体探针给出前后读次数与选择耗时，注明本地 harness 而非真机启动速度。使用一次完整 check 和精确五文件审阅，环境失败明确记录，不提交／推送／操作手机，完成后归档和清理本项材料。
