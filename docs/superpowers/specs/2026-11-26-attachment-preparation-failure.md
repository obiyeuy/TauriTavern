# 附件准备失败与消息发布

本地实际入口探针已确认四类问题：转换器拒绝后，消息与 Data Bank 仍上传原内容；普通发送按钮还把原内容交给模拟模型；`sendMessageAsUser()` 上传等待时切角色，消息被保存到新角色的聊天；给已有消息嵌入文件时，转换失败仍发布引用和 `MESSAGE_FILE_EMBEDDED`，并重置另一份主输入附件草稿。证据在 `output/verification/attachment-conversion-20261126/`。

在原功能和格式范围内收敛准备协议。文件上传请求沿 `requireOkResponse()` 拒绝 HTTP、传输与正文错误，收到非空路径才表示资源已准备。注册转换器拒绝即停止，不上传原字节或 data URL。保留原 MIME 匹配、转换器、编码、文件路径、消息／媒体字段和成功 URL；消息普通文本仍保留原字节编码方式，Data Bank 仍保存转换后的文本，没有新转换框架。

消息附件先收集本次成功上传的新引用，全部准备成功且目标仍有效后才一起加入原 `message.extra`。工作中的新上传结果不是已有状态的镜像；失败不发布部分消息附件。已经上传的有效副本不回滚删除，部分失败的错误保留原原因并列出实际路径。Data Bank 仍按文件独立发布已成功的结果，批量失败保留并刷新这些确认的部分结果，不承诺跨文件事务。

当前聊天位置从既有 owner、文件名和 integrity 派生，规则移到拥有这些事实的 `script.js`，消息准备和 Data Bank chat source 使用同一 getter。操作在首次异步前捕获；嵌入还在打开选择器前绑定原消息与回复候选。位置、消息成员关系或候选改变时停止新的发布，不能把旧操作写入新角色、另一楼层或另一个候选；合法 metadata 编辑不通过整对象缓存限制。没有新持久身份、宿主接口、错误标记或状态镜像。

发送的附件准备在用户消息入列前失败时，仅在原聊天仍在且输入框为空时恢复本次原始文字，保留文件选择；新草稿不被旧操作清空。API／slash 继续拒绝，正常发送、Agent 入口、嵌入、Data Bank、抓取和拖放各由实际入口呈现一次失败。现有 binary／size 校验布尔结果和提示保持，调用者遇到没有上传路径时停止，不报告抓取成功。

把隐藏的嵌入输入移出主附件 form，使两个选择器各自拥有清理范围，保留原 ID 与按钮。成功后只清理仍对应本次操作的选择；嵌入成功或失败都不清空主输入的附件。继续原事件时机、队列、保存规则与 neutral session/no-op，完整迁移两个消息准备入口及所有上传调用者。

扩展已有最高层附件覆盖，验证失败没有消息／引用／模型请求，原草稿及正文保持、一次原因、部分副本与成功重试，实际 role／swipe／嵌入与选择变化，成功媒体与文本形状。运行 focused、`pnpm run check`、逐路径自审和精确增量审阅，环境失败单列，归档后清理临时材料。不操作手机、真实账户或数据，不提交或推送。

调用者迁移补充：群聊无激活成员的原发送分支同样接管准备失败。普通与群聊入口通过原发送函数的可选同步 `onAttachmentError` 使用现有附件 presenter，catch 只包围准备阶段，避免重复原保存器的失败通知。嵌入校验结束后还须核对本次文件选择，旧校验不能读取给另一条消息选择的新文件；成功后的楼层编号从当前 canonical chat 派生。

发送和嵌入都向原准备函数传递本次捕获的 `selectedFiles`；省略时仍从原 input 读取。发送在 token 读取等首次异步前捕获，避免等待计数后把新草稿中的文件提前发送或清空。选择是本次工作输入，不是另一份持久状态；没有文件的发送也不接管后来选择的文件。
