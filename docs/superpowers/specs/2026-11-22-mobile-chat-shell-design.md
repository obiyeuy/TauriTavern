# TauriTavern 手机界面改造设计

## 目标

让 Redmi 手机上的日常聊天只保留清晰的核心路径：打开当前聊天、切换角色、查看历史、发送消息。角色卡和世界书继续使用迁移后的原始数据，不复制、不改写卡片正文。

## 现状发现

- 顶部存在多个图标入口，API、世界书、用户设置、背景、扩展、角色管理彼此分散。
- TauriTavern 已提供角色收藏热切换、标签文件夹、高级角色搜索、聊天 DOM 虚拟化和历史滑动按需加载。
- 类脑常见的“角色卡列在旁边”本质是角色书架/角色管理扩展：读取角色头像、名称、收藏和标签，生成一个可展开的抽屉或网格。
- 手机固定侧栏会压缩聊天正文，卡片数量较多时还会增加图片加载压力。

## 方案

1. 只调内置设置：风险最低，但角色切换仍需进入角色管理。
2. 内置设置加手机角色抽屉：推荐。聊天保持全宽，通过一个“角色”入口展开抽屉；抽屉提供收藏、标签、搜索和最近使用，点卡片后切换并自动关闭。
3. 完整第三方角色书架：功能最多，但会增加扩展扫描、更新和兼容风险。

采用方案 2。

用户后续要求直接从 GitHub 项目源码改造 App，并指定 `/Users/yyb/Projects/TauriTavern` 存放全部文件。因此改为内置手机导航并构建个人 APK。手机断开期间完成源码、自动验证和构建，安装验收待重连。

## 具体行为

- 日常聊天：保持全宽，默认启用聊天 DOM 虚拟化、历史按需加载、自动加载上次聊天和自动滚动。
- 角色入口：Telegram 式顶部会话栏左侧菜单打开导航抽屉；抽屉提供聊天、角色、历史和更多入口，角色页显示头像、名称、收藏状态和标签筛选；选择角色后自动切换到该角色最近聊天。
- 菜单整理：API、世界书、用户设置、扩展等高级入口收入“更多”；聊天页只保留顶部会话栏和底部输入框。
- 手机性能：启用紧凑输入区域、减少动态效果；关闭不必要的模糊、文本阴影、视觉小说背景和重复扫描型扩展。
- 保留能力：角色卡导入、世界书、正则、酒馆助手、聊天导出和 API 配置保持可访问；不修改生产服务器数据。
- 失败处理：角色抽屉加载失败时显示重试按钮；当前聊天和发送区不受影响。

## 验证

- 角色列表显示迁移后的 33 张卡并能按标签/收藏筛选。
- 点选角色后在同一界面打开对应最近聊天。
- 长聊天继续使用虚拟化和按需加载。
- API 配置保持“有效”，不额外发起模型生成请求。
- 手机上至少验证一次打开、切换角色、返回聊天、打开世界书和关闭抽屉。
